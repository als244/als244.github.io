Research

I build systems software for machine learning. Models keep growing and context lengths keep getting longer, but the fast memory packaged with GPUs is expensive, supply-constrained, and inelastic. How much of it do we actually need if we pair it with cheaper, slower memory? For compute-intensive workloads, surprisingly little, as long as data movement is hidden behind computation, which is possible even with limited transfer bandwidth. Model training, large-batch/low-interactivity inference, image and video generation, and robotics inference all fit this profile.

Our system, ShadowSpill, jointly plans how a workload executes (e.g., micro-batch sizing, chunking, task scheduling, recomputation, sharding, parallelism) and how its data moves between memory tiers. The same system serves three goals: matching performance with a fraction of the GPU memory, achieving higher throughput at equivalent GPU memory budgets, and training larger models or longer contexts than would otherwise be practical. Playground: Dataflow Simulator, a simplified version of the ShadowSpill planner that uses theoretical hardware constants to show the benefits of effective offloading.
